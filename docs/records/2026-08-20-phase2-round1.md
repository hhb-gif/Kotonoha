## 2. 技能硬调控方案落地（承接 approval-probe 结论）

```
技能开关 → 两层执行：
  软层：sendMessage 时 buildConstraintSegment() 把关闭的技能拼进 prompt 约束段
  硬层：events.mux 收到 approval/requested（越界升级审批）
        → skills.decideApproval(state, toolName)
        → POST /api/respond { outcome: 'rejected' | 'allowed-once' }
        → 审批帧无超时 + 跨连接重放 → respond 失败时 5s 后补一次 rejected 兜底
  边界（dsh 硬限制，UI 已注明）：
    - 沙箱内合法调用零审批，开关拦不住（仅软层约束）
    - 已存在会话权限不可外部修改（settings.update 只影响新会话）
```

7 技能：文献读取 / 文书撰写 / 终端术式 / 检索之眼 / 异界探访 / 奥义执行 / 越界放行（审批策略本身）。

## 3. 数据模型

| 键 | 内容 |
|---|---|
| `kotonoha:stories` | `{ stories: [{id, name, path, createdAt, lastActiveAt}] }`（同名故事=同一故事，update 路径/时间戳） |
| `kotonoha:saves:<storyId>` | `{ saves: [{id, name, sessionId, createdAt, lastActiveAt, preview}] }`（同名存档=覆盖） |
| `kotonoha:context` | `{ storyId, saveId }` 当前上下文（「继续」入口） |
| `kotonoha:skills` | `{ 'file-read':true, ..., approval:true }` |
| `kotonoha:settings` | 沿用（textSpeed/scene/showCharacter） |
| `kotonoha:save` | 旧单存档位 → init 时迁移为故事「Kotonoha」+存档「对话」后删除 |

## 5. 坑与对策

| # | 坑 | 对策 |
|---|---|---|
| 1 | opencli 后台标签冻结：事件循环停摆，任何交互/网络事件不处理 | close + open 新标签获得活跃期；交互全用 eval（一次性完成） |
| 2 | opencli `click`/`keys Tab` 为模拟输入，页面收不到事件；eval `.click()` 在冻结时同样无效 | 活跃期内 eval `.click()` + native setter 派发 input 事件 |
| 3 | npm install electron 二进制下载超时（github 源） | `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` 重装，38s 完成 |
| 4 | package.json 是 type:module，Electron 主进程若用 .js 会被当 ESM | 主进程/preload 用 .cjs 扩展名 |
| 5 | vite 构建产物默认绝对路径 /assets → file:// 加载失败 | vite.config base:'./' |
| 6 | 子 agent A 为过构建建了 SelectScreen 占位组件+样式 | 子 agent B 覆盖组件；清理 A 的占位样式段（styles.css 715-756） |
