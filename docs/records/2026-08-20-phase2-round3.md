## 1. ESC 面板新页签（子 agent 实现）

| 页签 | 内容 | 后端 |
|---|---|---|
| 会话 | 会话 ID 展示 + **Fork 新会话** + 重命名输入 | bridge.sessionFork / sessionRename（dsh session.fork / session.rename） |
| Git | 工作区路径 + Git 状态 / 提交 / 最近提交 | **dsh 无 shell 接口**（探测确认）→ 改为「请言叶执行」：经 sendCommandToAgent 发 prompt，输出回显到对话 |
| MCP | 服务器列表（防御式） | bridge.getMcpInfo（dsh mcp.list，不存在返回 null → 灰显提示） |
| 命令 | / 命令速查表（静态 8 条） | — |
| 凭据 | ref 状态徽标（已配置金色/未配置灰）+ 刷新 | bridge.getCredentialsStatus（credentials.describe，格式防御式解析） |

## 2. bridge.js 新方法

- `sessionFork()` / `sessionRename(label)`：会话管理
- `getGitStatus()`：发 prompt 请言叶执行 git status（返回提示文本）
- `sendCommandToAgent(text)`：busy 检查 + 包装 sendMessage 返回 {ok}
- `getCredentialsStatus()` / `getMcpInfo()`：防御式解析，失败返回 null
- 全部加入 default export

## 3. slash 命令（App.jsx handleSend 拦截，本地解析不进 dsh）

```
/help           命令列表 toast
/new            回主界面
/save [名称]    存档（默认当前存档名或「对话」）
/load           回主界面
/model          打开设置面板
/skills         打开 ESC 面板
/log            打开对话记录
/continue       提示已在当前对话
未知            提示 /help
```
> 背景：dsh 的 / 命令路由不暴露 HTTP（探测确认），故前端本地实现，与 ESC「命令」页签速查表一致。

## 4. 排查记录（重要）

- **CSS 覆盖失效坑**：main.jsx 原为 `import App` 后再 `import './styles.css'` → styles.css（旧 .main-menu-* 规则）排在最后，**覆盖组件 css**，且只覆盖「组件未写的属性」（如 styles.css 的 `flex-direction: column` 使菜单项纵向堆叠 106px 高）。
  **修复**：main.jsx 把 `import './styles.css'` 移到第一行（全局基线先行，组件样式后加载覆盖）；并从 styles.css 删除已迁移的「主界面菜单」整块（614-713 行）。
- **TDZ 崩溃**：handleSend 的 useCallback 依赖数组引用 `goMain`，但 goMain 声明在其后 → `Cannot access 'goMain' before initialization`，React 整树崩溃白屏（页面 root 空）。
  **修复**：handleSend 移到 goMain 定义之后。排查方法：eval 里 hook window error/unhandledrejection 再动态 import main.jsx 捕获错误。
- opencli 自查时 vite dev server 页面白屏（模块图旧）+ 冻结问题依旧：reload 后 eval 检查。
