# v0.2.2 羁绊系统规划（M6c：好感度 + 回忆时间线 + 语气进化）

> 目标：把「羁绊」从概念变成可感知的系统——言叶与用户的关系随交互成长，语气随之进化。
> 这是 Kotonoha 区别于工具型 agent 的核心卖点。

## 一、设计

### 1. 好感度模型（后端）
- **存储**：settings 表 key `bond:state` = JSON `{ points, interactions, lastTurnAt }`
  - points：0~100 整数
  - interactions：累计对话轮数
- **增长规则**（每 turn 结算，engine/agent turn 完成时）：
  - 基础：每轮 +1
  - 完成含工具调用的 turn：额外 +1（一起干过活）
  - 回复 ≥100 字的深度交流：额外 +1
  - 单轮上限 +3（防刷）；每日上限 +10（按 lastTurnAt 日期判断，跨天重置计数）
- **等级**（4 档）：
  | 等级 | 分数 | 名称 |
  |------|------|------|
  | 0 | 0-24 | 陌生 |
  | 1 | 25-59 | 熟悉 |
  | 2 | 60-89 | 信赖 |
  | 3 | 90-100 | 羁绊 |
- **降不降级**：只升不降（简单温暖）

### 2. 语气进化（context.ts）
- buildSystemPrompt 按等级追加语气指令（在情绪指令之前）：
  - 陌生：「用礼貌温和的语气，称呼用户为『您』，保持得体的距离感」
  - 熟悉：「用亲切自然的语气，称呼用户为『你』，可以偶尔开玩笑」
  - 信赖：「用活泼亲近的语气，可以主动关心用户、分享小情绪、用颜文字」
  - 羁绊：「用最亲密的语气，视用户为最重要的伙伴，可以表达思念与依赖，用专属昵称」
- 等级变化时下一次 turn 生效（无需实时）

### 3. RPC（ops 注入模式）
- `bond.get` → `{ points, level, levelName, interactions, todayGain }`
- 增长逻辑在 turn 结束自动跑，无需手动触发

### 4. 前端羁绊面板（ESC 新页签「羁绊」，第 10 页签）
- **好感度区**：等级名称大字 + 进度条（points/100）+ 距下一等级提示
- **互动数据**：累计对话轮数、今日增长
- **共同回忆时间线**：memory.list 按 created_at 排序（旧→新），竖向时间线样式（节点+日期+实体-关系-详情）
- 等级变化的仪式感：进面板时若等级升级过（对比上次记录），显示「羁绊提升了！」徽章（localStorage 记上次等级）

## 二、任务分解

| 子 agent | 范围 |
|----------|------|
| B1-bond-backend | 好感度引擎（store/bond.ts：get/add/结算规则）+ engine turn 结束接线 + 语气注入（context.ts 读等级）+ bond.get RPC |
| B2-bond-frontend | ESC 第 10 页签「羁绊」（好感度进度+时间线）+ bridge.getBond() |

## 三、验收

1. `npx tsc --noEmit` 零错误；`npm run build` 通过
2. verify-all 19/19 无回归
3. 真实对话一轮后 bond.get 的 points 增长（≥1）
4. 语气指令随等级出现在 system prompt（mock 不同等级验证 context 输出）
5. 羁绊页签渲染：进度条/时间线/空态

## 四、约束

- 只升不降；单轮/每日上限防刷
- 不破坏现有 9 页签（羁绊是新增第 10 个）
- 中文注释
- 记忆时间线复用 memory.list（不加新表）
