# v0.2.1 语音系统规划（M6b：让言叶开口说话）

> 目标：言叶的回复可用语音朗读出来——视觉小说沉浸感的关键一步。
> 原则：零新 npm 依赖（Web Speech API 原生），离线可用（系统语音包），可配置可关闭。

## 一、技术选型

| 方案 | 评估 | 结论 |
|------|------|------|
| **Web Speech API（speechSynthesis）** | 浏览器/Electron 原生、零依赖、系统语音包（含中文）、可调语速音调音量 | ✅ 主方案 |
| Windows SAPI（主进程 PowerShell） | 复杂、跨进程 | ❌ 不需要 |
| edge-tts / 云 TTS | 需网络+依赖+密钥 | ❌ 后续可选增强 |

## 二、功能设计

### 1. TTS Hook（src/hooks/useTTS.js）
```js
useTTS({ enabled, rate, volume, voiceURI }) => {
  speak(text, emotion),   // 朗读文本（按情绪微调 pitch）
  cancel(),               // 停止当前朗读
  voices,                 // 可用语音列表（zh-CN 优先）
  speaking                // 是否正在朗读
}
```
- **情绪映射 pitch**：happy=1.15 / sad=0.85 / angry=1.2 / love=1.1 / thinking=1.0 / surprise=1.2 / neutral=1.0（±0.15 微调，生硬感低）
- 语音包筛选：优先 `zh-CN`，列出所有供设置面板选择
- speechSynthesis 不存在（旧环境）→ 全部静默降级

### 2. 朗读触发（App.jsx）
- **model:done**（回复完成）→ 按句切分（。！？\n）→ 依次入队朗读
- 用户消息/系统提示**不朗读**
- **停止生成**按钮（已有 interruptSession）同时 cancel TTS
- 新 turn 开始（turn/start）→ cancel 上一段（防止叠音）
- 朗读时立绘 mouth 微动（可选：CSS 动画 class，简单实现）

### 3. 设置面板（SettingsPanel 新增「语音」区块）
- 开关：语音朗读（默认**关**——避免打扰，用户显式开启）
- 音色选择：下拉列出系统 zh 语音包
- 语速滑块：0.5x ~ 2x（默认 1.0）
- 音量滑块：0~100（默认 80）
- 设置持久化 localStorage（kotonoha:settings 复用）

### 4. 分句朗读细节
- 句子切分：`text.split(/(?<=[。！？!?…\n])/)` 保留标点
- 队列：speak 逐句，Utterance.onend 触发下一句
- 取消：speechSynthesis.cancel() 清队列
- 长句保护：单句 >100 字再切逗号

## 三、任务分解

| 子 agent | 任务 |
|----------|------|
| T-tts（单个） | useTTS hook + App.jsx 集成（model:done 触发/停止联动）+ SettingsPanel 语音区块 + CSS（如有需要） |

## 四、验收标准

1. `npm run build` 通过
2. 开启语音后：言叶回复完成自动朗读（中文语音包），情绪影响语调
3. 停止生成同时停止朗读；新对话不叠音
4. 设置持久化：重启后语音配置保留
5. 语音默认关闭，不影响现有用户
6. 现有功能零回归（build + 手动路径检查）

## 五、风险

| 风险 | 对策 |
|------|------|
| 系统无语包/非 Windows 语音差异 | voices 列表为空 → 开关禁用+提示「系统无可用的中文语音」 |
| 朗读与打字机音效打架 | 打字机 click 音量低+频率高，TTS 整句——并存可接受；设置里可分别关 |
| speechSynthesis 在 Electron 的兼容 | Electron/Chromium 完整支持；降级路径已留 |
